# Silkscreen legend + LLM-authored functional labels

**Status: planned 2026-07-07 (motivated by KC-7A3VEX). Not started.**

## Problem

KC-7A3VEX (USB-C PD trigger, switch-selectable 9/12/20 V) shipped "fab-ready" with a
silkscreen that tells the user nothing:

- No board name, revision, date, attribution (who/what made it — KiCraft), or board code.
- No functional info: the whole point of the board is "flip DIP switches to pick the
  voltage", and nothing on the board says which setting gives 9 V vs 12 V vs 20 V.
- No IO labels: input (USB-C PD) and output (screw terminal) carry no voltage/current
  markings. A user probing the terminal has no idea what to expect.
- The only text that *is* there — the leaf group label "PD TRIGGER" — is clipped by the
  board edge (see Phase 0).

The schematic already stamps a title block (`(title ...)`, `(rev "1.0")`,
`(comment 1 "Generated by KiCraft pipeline")` — `design/synthesis/emitter.py:346-350`).
The PCB has **zero** equivalent: the seed board is a bare `pcbnew.NewBoard()`
(`design/synthesis/kicad_pcb_stub.py:103`), and the only silk producers are per-leaf
group boxes (`autoplacer/brain/subcircuit_solver.py:126`) and the refdes legalizer
(`autoplacer/hardware/silk_refdes.py:58`).

## Design principles

1. **LLM authors content; deterministic code places it.** The LLM never emits
   coordinates or geometry — it emits a structured list of labels with semantic anchors
   ("table next to SW1", "label near J2"). A geometry pass in the build tail does
   placement, collision avoidance, sizing, and degradation. This keeps placement
   testable and keeps silk out of the "LLM said so" trust bucket.
2. **LLM runs in the web process at synthesis time, never in the build.** The build
   worker is no-LLM by design (files-as-IPC contract). The silk plan is committed to
   `state.json` as a top-level field (like `review_findings`), authored right after
   wiring/BOM in `_run_design` — same seam as `run_post_wiring_review`
   (`server/web.py:1911`, before `_drive_build_queue` at `:1927`). The build consumes
   it deterministically; `kicraft replay` stays $0 and reproducible.
3. **Never state what the design data can't back.** A wrong voltage table on silk is
   worse than no table. Every label passes a deterministic lint against state
   (refs must exist in BOM, voltages must appear in `architecture.rail_voltages` /
   functional spec / BOM notes) before it reaches the board.
4. **No silent drops.** If placement can't fit a label, it is dropped by ascending
   priority and the drop is recorded in artifacts + surfaced in the UI (same honesty
   rule as the rest of the pipeline).

## What the LLM gets and produces

Input: the geometry-free design digest that already exists for the electrical review —
`build_design_digest()` (`design/synthesis/electrical_review.py:143`) renders intent,
power nets, rail voltages, BOM (refs/values/MPNs), and the netlist with **pin function
names**. For KC-7A3VEX that digest contains everything needed to derive the CH224K CFG
table and IO ratings. Plus: brief, `functional_spec`, `bom.assumptions` (the DIP-voltage
mapping literally sits in an assumption string today).

Output: a versioned top-level state slot:

```json
"silk_plan": {
  "version": 1,
  "labels": [
    {"id": "dip-table", "kind": "table", "anchor": {"type": "component", "ref": "SW1", "prefer": "right"},
     "text": "V_OUT  1 2 3\n 9V    ON - -\n12V    - ON -\n20V    - - ON", "priority": 1},
    {"id": "out-rating", "kind": "io", "anchor": {"type": "component", "ref": "J2"},
     "text": "OUT 9/12/20V 3A MAX", "priority": 1},
    {"id": "in-rating", "kind": "io", "anchor": {"type": "component", "ref": "J1"},
     "text": "IN USB-C PD", "priority": 2}
  ]
}
```

`kind ∈ {title, attribution, io, table, note}`; `priority` 1 (must-have) … 3 (nice).
Text is ASCII-normalized at commit (stroke font + past mojibake lesson). The
title/attribution labels are NOT LLM-authored — they're deterministic (Phase 1) — but
they flow through the same placer.

## Phases

### Phase 0 — bug fix: clipped/off-board leaf group labels (small, standalone)

The "PD TRIGGER" label ran off the board edge. `_build_leaf_silkscreen()`
(`subcircuit_solver.py:126`) sizes the label to the leaf box; after compose the parent
outline can crop it. Fix in the parent stamp: clamp group-label text (and box polys)
to Edge.Cuts minus 0.2 mm margin, drop the text if it can't fit, and log the drop.
Touchpoints: `cli/_parent_stamp_subprocess.py:215-247` (where silk payload is stamped).

### Phase 1 — deterministic board legend (no LLM, ships value immediately)

Stamp on every board, front silk, no synthesis dependency:

- **Title** (project title, trimmed like `emitter._fit_title`), **rev** (mirror the
  schematic's "1.0"), **date** (UTC build date), **attribution + board code**:
  `KiCraft · KC-XXXXXX`. Board code is server-side knowledge, so the server writes it
  into the new state slot when creating/enqueuing the build (id-less/self-eval runs
  fall back to stem + date, no code).
- New module `autoplacer/hardware/silk_legend.py`: given the promoted routed board,
  find free silk regions (board outline minus footprint courtyards minus existing
  silk bboxes), place the legend edge-anchored (bottom strip first, then top),
  honoring DRC rules: text ≥0.8 mm high / ≥0.08 mm thick
  (`design/synthesis/kicad_pro.py:38-41`), ≥0.2 mm off the edge, never over pads/mask
  openings.
- **Insertion seam:** `cli_app._promote_verify_fab()` between promote (`cli_app.py:4126`)
  and the fab-gate verify (`cli_app.py:4135`), as its own pcbnew subprocess (same
  pattern as `_parent_stamp_subprocess`; pcbnew-in-subprocess is the house rule after
  the strip SIGSEGV). Running before `_verify_routed_board` means the existing DRC
  pass sees the added silk; silk classes stay MINOR (`scoring/drc_check.py:16-18`) so
  a tight board degrades scores, never blocks fab.

### Phase 2 — LLM silk-plan authoring (content only)

- `design/synthesis/silk_plan.py`: `author_silk_plan(state, project_root) -> SilkPlan`,
  calling the LLM via the existing client plumbing (`server/client.make_client` +
  `Settings.from_env().for_review()` — same imports `_maybe_electrical_review` already
  uses, `cli_app.py:3795-3826`; cost lands in the same spend ledger).
- Deterministic lint before commit: every `anchor.ref` must exist in `bom.parts`;
  numeric claims (voltages/currents) must be corroborated by `rail_voltages`,
  functional spec text, BOM values/notes, or the brief; length caps; ASCII
  normalization. Uncorroborated labels are dropped with a logged reason (reuse the
  refdes-anchored corroboration idea that fixed review-gate over-blocking).
- Wire into `_run_design` next to `run_post_wiring_review`; commit as top-level
  `state.silk_plan`. Missing slot ⇒ build falls back to Phase 1 legend only (old
  projects and replays keep working).
- Failure is soft: no key / LLM error / lint-empty ⇒ legend only, never a build fail.

### Phase 3 — anchored placement (tables + IO labels)

Extend `silk_legend.py` to place component-anchored labels:

- Candidate boxes on the anchor's four sides (prefer hint), expanding search radius;
  collision set = courtyards + pads + existing silk + already-placed labels + edge
  margin. Text metrics via pcbnew's stroke-font bbox, floor 0.8 mm; try 1.0 → 0.8 mm.
- Priority-order placement; on failure drop lowest priority first. Dropped labels go
  into `artifacts` (e.g. `silk_dropped: [...]`) and a build-log line — surfaced in the
  UI next to the layout panel.
- Back-side fallback for priority-1 labels whose anchor component sits on B.Cu
  (`BomPart.side`): needs a small mirrored-text helper (SetMirrored + justify swap) —
  today nothing mirrors gr_text; `subcircuit_solver.py:157` hardcodes `F.SilkS`.
- DIP-switch tables get one extra deterministic guard: the table's switch-position
  column count must equal the switch's position count (from the symbol/footprint pin
  count) or the table is demoted to a plain note.

### Phase 4 — surfacing + scoring

- Stage tabs: show the authored silk plan (read-only card) once committed, so the user
  sees planned silk before/without opening KiCad; later: allow edit + re-commit.
- Renders already pick the silk up for free: `fab_export` exports
  F/B.Silkscreen gerbers and re-renders `board_3d.png` from the final board.
- Scoring: small bonus for legend presence; count `silk_dropped`; keep silk DRC MINOR.
- Self-eval rubric line item ("board self-describes: name/rev/maker + at least one
  functional label on functional boards") so regressions show up in the 28-brief suite.

## Costs & risks

- **LLM cost:** one extra call per project at review-model rates (minimax-m3) — same
  order as the electrical review, i.e. cents. BOM retries dominate pipeline cost; this
  is noise.
- **Wrong-content risk:** bounded by the lint (only corroborated claims) + priority
  drop + UI visibility. The DIP table is the riskiest artifact (ON/OFF orientation);
  the Phase 3 pin-count guard + showing the table in the UI mitigate; a wrong table
  needs the user to catch orientation — acceptable for v1, flagged in the card.
- **Space-constrained boards:** the placer degrades (shrink → relocate → drop with
  record). Dense boards simply get the legend on the least-bad edge or nothing, never
  a DRC-blocking overlap.
- **Replay determinism:** all content comes from `state.json`; the placer is pure
  geometry. `PYTHONHASHSEED` caveats unchanged.

## Out of scope (this plan)

- Rebuilding old projects to add legends (KC-7A3VEX itself keeps its patched 3D fix;
  silk arrives on its next rebuild).
- Logo/graphic silk (bitmap → polygon); text only for v1.
- User-editable silk plan UI (Phase 4 note; read-only first).
